### Release 描述（0.3.6，已发布）

**新增**

- 下载支持断点续传：应用退出、崩溃或取消后再次继续，会从已下载的分片接着下载（复用 yt-dlp 原生 HLS 续传能力）
- 下载记录「更多」菜单新增「重新下载（清空断点）」：清除该任务的分片缓存后从头开始
- 通知设置新增「任务完成 / 任务失败 / 全部完成汇总」三个事件开关，以及「提示音」开关（默认关闭）

**改动**

- 中断任务的按钮文案由「重试」改为「继续」，中断提示改为「应用退出，任务已中断，可继续」
- 移除下载记录时，同时清理该任务未完成的临时文件（`.part*` / `.ytdl`）；已完成的成品文件不受影响
- 下载失败通知正文附带第一行关键失败原因
- 通知总开关说明更新：窗口隐藏或最小化时发送系统通知，应用在前台时显示应用内提示

**优化**

- 应用在前台时，下载事件以应用内消息呈现；开启提示音后播放内置短提示音（WebAudio 合成，不额外打包音频文件）
- 队列全部结束时汇总本轮成功与失败数量；全部取消的批次不发送汇总
- 清理临时文件按「输出目录 + 成品名」前缀匹配，同目录存在同名进行中任务时自动跳过，避免误删断点
- 修复跨平台路径解析：备份恢复等场景中的 Windows 风格路径在 macOS / Linux 下也能正确取到文件主干

**兼容性**

- 配置新增 `notify.events`（success / failed / allDone）与 `notify.sound`，旧配置自动补默认值（完成、失败开；汇总、提示音关），`schemaVersion` 仍为 1，可直接覆盖安装
- 下载记录 `jobs.json` 格式未变；旧版明文凭据迁移逻辑不变
- 断点续传依赖 yt-dlp 自身行为：取消或中断不会删除已下载分片，「重新下载」才会主动清空
- 凭据（代理 / Cookie / Referer / 附加参数）仍只保存在内存中，应用重启后继续或重试需要重新填写
- 未实机验证项：Windows NSIS 安装冒烟、macOS / Linux 安装包与自启、真实下载的前台通知与提示音

## 8. CI：Ubuntu 单测（已修复）

- run `44008967361`（提交 `7bdad85`）：frontend、rust (macOS)、rust (Windows) 通过；rust (ubuntu-22.04) 失败，`cargo test` 约 50 分钟后被整体杀掉，日志缺失
- 根因：`kill_tree` 通过 `kill -9 -<pid>` 子进程清理进程组，procps 的 `kill` 对负 PID 参数解析不一致，信号实际打到了调用方自己所在的进程组（runner 的组），导致测试进程与 `timeout` 一起被 SIGKILL，而真正的目标 `sh`/`sleep` 存活为孤儿进程
- 修复：改为直接调用 `kill(2)`（`src-tauri/src/core/proc.rs`），仅在目标确为进程组组长时按组发送；调度器与下载器共用该实现；命令执行在终止后增加兜底期限，回收失败也不会永久阻塞
- 验证：run `44029486162` 四平台全绿，Ubuntu 63 个单测 0.86s 通过；新增 `core::proc::tests::kills_child_in_its_own_process_group` 防回归
